01

Separate installation to match the runtime roles让安装边界与运行职责一致

An engine worker connects to an MP server, but today installing its connector also installs server code, storage backends, the in-process runtime and their requirements. Those are needed on the server side; they are not all needed in the worker image.

引擎 worker 连接 MP 服务端，但目前为了安装连接器，也会装入服务端代码、存储后端、进程内运行时及其依赖。这些能力在服务端有用，却不必全部进入 worker 镜像。

The runtime roles already exist. The work here is to remove the imports that make a client module load server code, then package the two roles separately from the same source tree. Shared contracts stay client-owned so both sides use the same definitions.

运行职责本来已经分开。本次改动去掉会连带加载服务端代码的客户端导入，再从同一源码树分别打包。共享契约归客户端所有，两侧继续使用同一份定义。

Why keep more than an RPC stub? The worker still needs its vLLM/SGLang adapter, tensor layouts, registration and local transfer machinery. Removing those too would move or redesign the existing integration. This draft keeps that worker behavior and reduces what it must install.

为什么客户端不只保留 RPC？worker 仍需要 vLLM/SGLang 适配、张量布局、缓存注册和本地传输能力。再拿掉这些模块，就需要迁移或重做现有集成。本草稿保留这些 worker 职责，收紧其安装范围。
